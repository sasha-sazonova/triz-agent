# DEEP-промпты: 9 частей АРИЗ-85С
> Используются при режиме DEEP (methods/DEEP_ARIZ85C.md). Каждая часть = один ход агента
> (или субагента) → артефакт `projects/<задача>/deep/N_*.md`. Не имитируй шаги: содержательное
> решение для ЭТОЙ задачи или честный «тупик, потому что…».

## Часть 1 — Анализ задачи → `deep/1_analysis.md`
Шаги: 1.1 записать условия мини-задачи (всё остаётся, вредный фактор исчезает) ·
1.2 определить конфликтующую пару (инструмент ↔ изделие) · 1.3 сформулировать
 administrativную формулировку · 1.4 выбрать конфликтующую пару для схемы конфликта ·
1.5 развёрнутая схема конфликта (ТП-1) · 1.6 усиленная схема (ТП-2: довести до предела) ·
1.7 выбрать схему для продолжения (обосновать: какая ветвь даёт главный полезный эффект) ·
1.8 уточнить ТП · 1.9 актуализированная формулировка мини-задачи.
Выход обязательно содержит: ТП-1, ТП-2, выбранную ветвь + обоснование.

## Часть 2 — Анализ модели задачи → `deep/2_model.md`
2.1 оперативная зона (ОЗ) — минимальное пространство конфликта · 2.2 оперативное
время (ОВ) — время конфликта + время «до» (предыстория) · 2.3 вещественно-полевые
ресурсы (ВПР): инструмент, изделие, среда, надсистема — таблицей «ресурс | свойство |
что может дать бесплатно».

## Часть 3 — ИКР и ФП → `deep/3_ikr_fp.md`
3.1 ИКР-1: «X-элемент, не усложняя систему и не вызывая вредных факторов, САМ
устраняет <вред> в ОЗ за время ОВ, сохраняя способность выполнять <полезную функцию>» ·
3.2 усиленная формулировка ФП на X-элемент/ОЗ · 3.3 ММЧ-эскиз (что делают «человечки»
в ОЗ) → перевод на язык веществ/полей · 3.4 ИКР-2 (максимально приближённая к идеалу
формулировка решения) · 3.5 проверка ФП на осуществимость по уровням (макро/микро/подход).

## Часть 4 — Мобилизация ВПР → `deep/4_resources.md`
4.1 комбинации ресурсов (смесь, «пустота», поле+вещество) · 4.2 ресурсы времени
(паузы, до/после, предварительное действие) · 4.3 ресурсы пространства (соседние
объёмы, другая сторона, внутренние полости) · 4.4 функциональные ресурсы (система уже
что-то делает «бесплатно») · 4.5 производные ресурсы (изменённые состояния имеющегося).
Итог: рейтинг ресурсов по близости к ИКР.

## Часть 5 — Информфонд → `deep/5_informfund.md`
5.1 выборка 76 стандартов (класс 1-5 по типу ВС-поля) — канонический список:
  **`knowledge/76_standard_solutions.md`** (читать его, не вспоминать по памяти) ·
5.2 физэффекты для требуемого действия (effects_database + science-search) ·
5.3 принципы (матрица по ТП + frequency-fallback) · 5.4 аналоги из патентов/статей
(researcher/patent-search, асинхронно с cron-забором) · 5.5 законы эволюции: какой
тренд подтверждает направление — справочник **`knowledge/evolution_trends.md`**.
Дополнительно: разделение ФП — `knowledge/separation_principles.md`; термины —
`knowledge/glossary.md`; конспект АРИЗ-85С — `knowledge/ariz_85c.md`.

## Часть 6 — Изменение/замена задачи → `deep/6_retask.md`
6.1 переход в надсистему (решать задачу надсистемы) · 6.2 переход к подсистеме ·
6.3 инверсия задачи (анти-задача) · 6.4 проверить: не решается ли ТП-2 вместо ТП-1 ·
Если ни один сдвиг не нужен — короткая запись «задача остаётся, причины: …».

## Часть 7 — Анализ ответа → `deep/7_verify.md`
7.1 проверка по ИКР (введённые элементы/функции ≈ 0?) · 7.2 физика: законы сохранения,
порядки величин (масса/энергия/время/габариты) · 7.3 побочные эффекты и новые вредные
факторы · 7.4 патентная чистота (patent-search/researcher) · 7.5 применимость решения
к другим системам (запас для части 8).

## Часть 8 — Применение ответа → `deep/8_apply.md`
8.1 развитие решения в надсистеме · 8.2 использование решения по-новому (другие
системы/рынки) · 8.3 формулировка обобщённого принципа (что перенесли в базу знаний) ·
8.4 ближайшие инженерные шаги (что собрать/посчитать/спросить).

## Часть 9 — Анализ хода решения → `deep/9_retro.md` + `.learnings/TRIZ_LEARNINGS.md`
9.1 сравнить ход с теоретическим (где ушло не по АРИЗ) · 9.2 что сработало сильнее
ожидаемого · 9.3 записать в LEARNINGS: паттерн «симптом → приём» · 9.4 предложения
в базу знаний (новый эффект/кейс/уточнение промпта).

## Правила ведения DEEP
- Одна часть — один артефакт; между частями состояние на диске (gate control)
- Ошибка в части 2-3 → правь вниз по цепочке, не строй на сломанном
- Параллельные ресёрчи — researcher + cron (+20 мин), цикл не блокируют
- После части 4 допустим возврат на LITE-этапы 3-6 (обогащённый ресурсами)
